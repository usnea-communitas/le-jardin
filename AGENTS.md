# AGENTS.md — Le Jardin

Guidance for coding agents (Codex, Claude Code and others) working in this repository. People should start with [README.md](README.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

Maintainer workspace: if an untracked `STAV.md` exists in the repo root, read it first — it holds the current status and hand-off notes (it is intentionally not committed).

## What this is

Le Jardin is a story-led educational browser game about designing a living permaculture garden in Menet, France. It is a static site with one Vercel Function (the AI "Living Lesson") and no database; progress is saved in the browser. `main` deploys automatically to production at <https://permaculture-garden.vercel.app/>, so keep it releasable. Code is MIT, media CC BY-NC-SA 4.0.

## Canonical source and generated files

| Edit | Role |
| --- | --- |
| `Permaculture Garden v2.dc.html` | The canonical source: template, styles and the game logic class |
| `lib/` | The rules of the game (`economy.js`, `community-table.js`, `seasons.js`, `acts.js`, `wildlife.js`), the i18n runtime, the deterministic Living Lesson engine, workshop mode and playing without a connection |
| `api/garden-reflection.js` | The only server boundary (model call, limits, fallback) |
| `assets/` | WebP images, MP3 audio, fonts and `assets/i18n/catalog.<locale>.json` |
| `scripts/` | Build, checks, unit tests and Playwright journeys |

- The rules of the game live in `lib/` and decide; the canonical source keeps every word, picture and sound and asks them ([docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)). Rules take what they need as arguments and return no words; a random number is drawn by the game and passed in. Whoever touches a rule still in the canonical source first moves it to `lib/` and tests it (`npm run test:rules`); `scripts/test-rules-words.mjs` keeps the rules and the words in step.
- `index.html`, `game.fragment.html`, `game.logic.js` (the game's logic class, so the browser compiles it as a script) and `offline-manifest.json` (and the version line in `sw.js`) are generated by `npm run generate`. Never edit them by hand; regenerate after every source or asset change and commit them together. CI fails when they are stale.
- Playing without a connection (`lib/offline.js`, `sw.js`): every file under `assets/` must belong to an offline group in `scripts/offline-manifest.mjs` (or stay online, like videos); the build stops on a file that belongs to none. The service worker is registered only after a player downloads the game; never register it for everyone.
- Images are WebP only (the build refuses PNG references; the share preview `assets/story/share-menet.jpg` is the one JPEG, for social networks) and audio is MP3. `vercel.json` only sets headers: security headers and cache for fonts and media, no build or routing.
- The palette footer shows the version from `package.json`, filled in at build time.
- `catalog.en.json` is the source catalogue; all nine catalogues must keep the same keys and placeholders.
- The Garden's recorded voice: `assets/i18n/audio.cs.json` and `audio.fr.json` list each language's 49 recordings with the spoken text (English is the fallback). After changing a recording or its text, run `node scripts/sync-audio-captions.mjs <locale>` so the subtitles say what the voice says; `npm test` (`scripts/test-voice.mjs`) fails otherwise, and also when a recording is missing or lacks its length header. `scripts/normalize-voice.mjs` levels new takes. Media come from ElevenLabs first.
- Workshop mode (`?workshop=1`) lives in `lib/workshop.js` and keeps its garden and log under their own storage keys; never let it touch `permagarden_v2`. The facilitator guide in `docs/facilitator/` is hand-written in English, Czech and French, except its challenge chapter, which `node scripts/facilitator-guide.mjs` generates from the catalogues together with the QR codes and PDFs: run it after changing the guide, a challenge or a translation, and commit the results together (`npm test` fails on a stale chapter).

## Before committing

```sh
npm run generate        # rebuild index.html, game.fragment.html and game.logic.js
npm test                # structure, resources, i18n catalogues, Living Lesson engine and API, the rules of the game, garden score
npm run test:e2e:core   # the browser journeys CI runs; first `npx playwright install chromium`
```

After a production deployment, `.github/workflows/production-smoke.yml` checks that the live site serves the deployed commit and plays (`npm run test:production`).

Changes reach `main` through pull requests: work on a branch (`claude/<id>-…` or `codex/…`), open a pull request and merge it once the CI jobs are green. Every merge deploys to production. Do not push to `main` directly or rewrite its history, and keep the `backup/main-before-graft` branch.

When you change layout, interaction or text, also run the relevant journeys (`npm run test:e2e:*`, or `node scripts/e2e-*.mjs` against `node scripts/static-server.mjs 8787`) and look at desktop, tablet and phone sizes in more than one language. Do not send test traffic to the live Living Lesson API: every model call costs credit.

## Product constraints

Read [PRODUCT.md](PRODUCT.md) before changing behaviour or copy. In short:

- six-act learning progression and deterministic scoring; the AI reflection never decides rules, points or outcomes;
- community gifts never turn into personal currency;
- the model only receives the anonymous garden summary described in the README; without it the game shows a clearly labelled offline lesson;
- multiplayer is planned but deferred; the Build Week repository, deployment and Devpost entry are frozen records;
- never claim an award or an Erasmus+ affiliation.

Contribution rules, commit style and the add-a-language checklist are in [CONTRIBUTING.md](CONTRIBUTING.md); release notes in [CHANGELOG.md](CHANGELOG.md) and `docs/handoffs/`; security reporting in [SECURITY.md](SECURITY.md).
