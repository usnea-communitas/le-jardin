# Contributing to Le Jardin

Thank you for your interest in the garden. Contributions of every size are welcome: a corrected translation, an accessibility finding, a bug report from a phone, a playtest observation from a workshop, or a new learning challenge idea.

## Ways to help

- **Report a bug** — open an issue with the browser, device, language and the steps to reproduce. Screenshots or the exported garden certificate help a lot.
- **Improve a translation** — the catalogues live in `assets/i18n/catalog.<locale>.json`; `catalog.en.json` is the source. Fix the text, keep the keys, and run `npm run check:i18n`. Terminology decisions are recorded in `assets/i18n/LOCALIZATION_GLOSSARY.md`; follow them or propose a change there.
- **Add a language** — copy `catalog.en.json` to `catalog.<locale>.json` and translate every value. Register the locale in `SUPPORTED_LOCALES` in `lib/i18n.js` and `lib/living-lesson.js`, in `LANGUAGE_OPTIONS` and `LANGUAGE_NAMES` in `lib/i18n.js` (the language menu) and in `scripts/check-i18n.mjs`. For the Living Lesson, add the language to `LANGUAGE_NAMES` in `api/garden-reflection.js` and give its language guard about 40 common words in `LANGUAGE_PROFILES` (a non-Latin script needs a script check in `outputMatchesLocale` instead); without them every model answer in that language is replaced by the offline lesson. Then run `npm run check:i18n -- --require-all`.
- **Share playtest feedback** — if you ran the game with a group, tell us what confused people, what they enjoyed and which lesson landed. Open an issue tagged `playtest`.
- **Propose educational content** — new design connections, wildlife relationships or challenge questions should come with a short note on the ecological reasoning and, where possible, a source.

Please open an issue before starting a large change so we can agree on the approach.

## Development workflow

Requirements: Node.js 22+ and npm (the API tests use `module.registerHooks`, available from Node 22.15).

```sh
npm ci
npm run generate
npm test
node scripts/static-server.mjs 8787   # http://127.0.0.1:8787/
```

The one rule that matters most:

> **Edit `Permaculture Garden v2.dc.html` and the files in `lib/`, `api/`, `assets/` and `scripts/`. Never edit `index.html` or `game.fragment.html` by hand — they are generated by `npm run generate`.**

Before opening a pull request:

1. `npm run generate` — so the generated files match the canonical source (a check will fail otherwise).
2. `npm test` — structural checks, i18n catalogue checks, Living Lesson engine and API tests.
3. If you changed layout, interaction or text, run `npm run test:e2e:core` (CI runs it too) and the relevant Playwright journey (see the README). If you cannot run Playwright, say so in the pull request and describe how you tested manually.
4. Keep the fair-share rule intact: community gifts must never turn into personal currency, and the AI reflection must never decide rules, points or outcomes.
5. Keep changes focused; one topic per pull request.

## Pull requests

- Describe **what** changed and **why**, and which surfaces (desktop, tablet, phone; which languages) you verified.
- Reference the issue you are addressing.
- The maintainer reviews every pull request personally. Expect questions rather than silent rewrites.

## Commit messages

Short imperative summary line, then a body if the change needs explanation. English is preferred; Czech is fine for Czech-specific content.

## Code of conduct

This project follows the [Contributor Covenant](CODE_OF_CONDUCT.md). Be kind — this is a garden.
